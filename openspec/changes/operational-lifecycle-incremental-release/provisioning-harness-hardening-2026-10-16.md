# Provisioning harness hardening — October 16

Test tooling only; no application/SQL or historical evidence changes. Fresh staging identity, exact source review, authoritative absence/ownership guards, zero retries, immutable receipts, postflight and independent review/test gates remain mandatory. Failed Oct13 identities and private role files must not be reused or erased.

Sign-in records only actor slot, fixed substage/outcome/error code and exact staging password-token HTTP status (or null). It never persists raw errors, response bodies, request headers, tokens, credentials, screenshots or HTML. Authentication status alone does not prove dashboard hydration, Synced readiness or authoritative role checks. Navigation is bounded to 30 seconds; each UI/sign-in readiness action uses 20 seconds.

Every verification context closes through an independent three-second bound, including page-creation failure. Verification promises settle before parent resource cleanup. Primary operation failure survives a cleanup failure; cleanup-only failure is not success. Admin context and browser close in context-then-browser order under separate three-second bounds. An additional immutable browser-cleanup receipt records sanitized outcomes without changing old receipt paths. Missing cleanup receipt fails closed. These Promise bounds limit awaiting cleanup, not the operating-system process lifetime: an unresponsive browser transport can still require an independently reviewed external watchdog; this change does not claim a hard whole-process timeout or kill unrelated processes.

Offline fake-resource cases cover every sign-in substage, timeout versus generic error, successful sequence, exact-origin auth status, no body access, synchronous/rejected/hanging close, independent browser close, primary failure precedence and cleanup-only failure. Run browser-safety nodechecks, provisioning safety and Playwright harness contract tests, static checks and TypeScript/lint before freeze. No live call is part of these tests.
