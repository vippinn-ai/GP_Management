# Independent staging test plan

## Execution rules

- Clean worktree, approved SHA, reusable Playwright/direct-DB scripts, and `retries: 0`.
- Unique `normops-YYYYMMDD-HHMM-<case>-<n>` IDs for every run/entity/mutation/audit/customer.
- Never rerun ambiguity with a new ID; reconcile, then replay only the same ID where specified.
- Persist request body/response/database/timing/console/network/cleanup evidence as immutable JSON with SHA-256. Never persist authorization, API-key, cookie, password, or other credential headers in evidence.
- Capture old deployed definitions, ACLs, proconfig, flags, publication, compatibility hash/version/bytes, and rollback SQL before install.
- Capture the complete `operational_events` policy set including permissive/restrictive mode, the recursive role closure inherited by `authenticated`, and the access helper definition hash, normalized-body hash, owner, security mode, volatility, configuration, and ACL. The bootstrap install must accept exactly one applicable PERMISSIVE authenticated tenant-helper SELECT/ALL policy and reject extra public/direct/inherited-role or RESTRICTIVE-only alternatives; it must rebind that exact RLS/policy/publication/helper evidence at install and rollback time. The immutable generated read-only postflight must bind the exact preflight snapshot, while the reviewed standalone postflight independently rejects body, owner, volatility, extra configuration, grant-option, non-EXECUTE, missing required-principal, and unauthorized-grantee drift.
- Verify the captured bootstrap postflight through a separate fail-closed wrapper that requires the raw result's exact run ID and source commit, proves that commit exists, hashes the reviewed SQL blob from that commit as well as the working reviewed SQL, preflight, install, postflight SQL, rollback, and raw result, validates the exact payload key/type set and actor UUID, and confirms exact staging identity, clean preflight mutation floor, payload ceiling, unchanged `app_state`, and installed function/security evidence. Candidate performance must bind both lifecycle and bootstrap manifest/verification pairs, require bootstrap identity equality with the active fixture `appStateAfter` and frozen dataset `app_state`, correlate every available bootstrap collection count to that dataset, and reject either identity independently. Record exact hashes of the performance runner, Playwright configuration, and specification in both evidence manifests; candidate execution must reject a baseline created by a different harness revision.
- Run `npm run test:e2e:staging:operational-v2:static` to lint and no-emit type-check every Playwright spec selected by `playwright.operational-v2.staging.config.ts`; focused checks of only newly edited specs are insufficient.
- For an already-installed v2 function correction, prove the dedicated reinstall builder rejects a missing function, inconsistent definition hash, owner/configuration/ACL drift, dirty operational floor, and incomplete `app_state` identity; verify its install contains only the three reviewed v2 definitions, preserves preflight owner/ACL state, is atomic and immutable, and its rollback restores those exact three preflight definitions without touching unrelated functions or data.
- Exercise reinstall guards against deployed PL/pgSQL bodies containing CRLF and LF line endings; the SQL-side body normalization and boundary-whitespace trimming must produce the same canonical hash as the builder.
- Cleanup must preserve the primary assertion or runtime failure. No selected spec may throw from a `finally` block or otherwise replace the original failure with a cleanup failure.
- Every fallible finalization step must run through the shared settled cleanup guard. Independent steps continue after a cleanup failure; the primary failure is rethrown first, while one or more cleanup failures are reported only after a successful primary path.

## Functional and parity matrix

- Active timed/unit-sale hop; edited start; stale client start cannot overwrite canonical start.
- Active and paused/open-pause session reject; tab reject with items, variants, cigarettes, combos intact.
- Game-to-game multi-hop, game-to-new-tab, game-to-existing-tab, final checkout, receipt, and single consumption.
- Reject continuation consumer, release source hops, recover later exactly once.
- Dashboard availability, continuation banner, activity, bills, receipts, customers, analytics, inventory, hard refresh, logout/login, and mobile viewport.
- No bill/payment/stock/inventory effect from hop or reject.

Reusable suite ownership:

- `operational-lifecycle-v2-continuations.e2e.ts`: unit-sale hop with canonical mode/item/inventory/bill-line preservation and exact one-time final stock decrement/movement; new/existing consumables-tab continuation; three-consumer exclusivity; reject-and-recover; exact direct RPC timing/body, event/audit actor, browser-error, and unresolved-entity evidence.
- `operational-lifecycle-v2-recovery-realtime.e2e.ts`: committed/lost response; configured 20-second critical-acknowledgement waiter expiry; manual same-ID replay; realtime-first/response-first; offline gap; controlled duplicate realtime frame; observer-panel unmount/reconnect.
- `operational-lifecycle-v2-hop-mutation-races.e2e.ts`: hop versus timing, pause, resume, add-item, and remove-item writes, using distinct actors and accepting only success or exact `session_not_open`; reconcile the canonical session, closed pause, item/bill-line outcome, event, audit, actor, console, pending queue, and unresolved-session ledger.
- `operational-lifecycle-v2-concurrency.e2e.ts`: same-target races, exact 20-by-3 latency sampling, and 50 unrelated-target overlap/reload pairs.
- `operational-lifecycle-v2-downstream-parity.e2e.ts`: canonical bill/line/payment, Bill Register/receipt, hard refresh, mobile viewport, and logout/login parity.

## Negative, security, idempotency

- Missing/wrong organization/kind/type/entity/audit; outer-inner mismatch; malformed JSON/arrays; empty reason.
- Omitted and empty-string mutation kind/entity type for all three lifecycle RPCs return `invalid_payload`; the proof helper preserves the original PostgreSQL SQLSTATE when exception detail is not JSON.
- Future/end-before-start/malformed timestamp; missing canonical start; missing/foreign/multiple open pause; audit collision.
- Missing/closed/billed/rejected/wrong-organization target.
- Anonymous, inactive, wrong organization, unsupported role, actor spoof, and forbidden compatibility-version authority.
- Same ID/same intent returns one canonical result; same ID/different intent fails `mutation_identity_mismatch`.
- Mutation, audit, and event actor equals authenticated JWT subject.
- Forced late failure rolls back all domain/mutation writes and leaves `app_state` unchanged.

## Race, realtime, recovery

- hop/hop, reject/reject, hop/reject, checkout/hop, checkout/reject, hop/timing/pause/resume/item mutation.
- continuation start/link/new-tab double consumption; reject consumer versus new consumer.
- unrelated session/session, session/tab, and tab/tab pairs both succeed without global serialization.
- Direct two-client calls retain exact request/response/timing evidence; same-target cases prove winner actor attribution and the read-only post-test reconciliation proves every losing mutation/audit/event rolled back.
- realtime-before-response, response-before-realtime, reversed hydration completion, reconnect/gap/duplicate/unmount.
- lost response and waiter timeout recover with same mutation ID, exactly one effect, no automatic resend.
- 50 two-client reload-versus-mutation overlaps end with database parity before writes become enabled.

The rollback-only DB proof and the frozen/candidate 30-load comparison run before any mutating browser case so both performance runs are bound to the same exact normalized content fingerprints. Functional and concurrency cases run only after candidate performance passes. SQL-editor transport may preserve CRLF inside dollar-quoted function bodies, so catalog body and definition hashes must normalize CRLF and lone CR to LF before comparison. The temporary RPC must explicitly revoke `service_role` as well as `PUBLIC` and `anon`, then prove its effective ACL contains only non-grantable `EXECUTE` for `postgres` and `authenticated`.

When the clean staging snapshot is below production scale, a separate one-shot staging-only synthetic fixture gate is mandatory. It uses deterministic terminal normalized rows at the full verified production table counts plus a representative 25% sample of each missing compatibility `AppData` collection, followed only by structured synthetic audit-object padding to the verified production byte size. This is conservative for the normalized candidate because it processes more structured normalized rows than the legacy compatibility bootstrap. The fixture also binds exact current-window bill/payment/movement counts, production pending-count coverage, active catalog coverage, null contact values, and zero stock/payment effects. Only aggregate collection and workload-shape counts are derived from the hash-bound production backup; no production row or compatibility document is copied into the fixture or evidence. The private registry stores identity metadata only. Full fingerprints cover all seeded tables plus `activity_events`, `analytics_dirty_dates`, and `inventory_report_dirty_dates`; every indirect trigger is guarded and transactionally suppressed/restored. The temporary authenticated RPC must be absent at preflight, exact-org bound, source/owner/ACL/definition identified while active, and absent after cleanup. The reusable Playwright gate must verify the deferred Inventory request returns the expected recent movement count and no remote error banner. A rollback-only apply/cleanup proof, exact postapply verification, and exact cleanup/postrollback verification are mandatory. Baseline and candidate bind the same scaled snapshot and fixture verification. Cleanup runs before functional cases and must restore the exact original `app_state`, counts, fingerprints, workload shape, auxiliary state, trigger state, and clean floor.

## Performance gates

Use guarded disposable production-logical-size staging state with exact restore artifact/hash.

The full-table fingerprint helper is staging-only test instrumentation and is not part of the production lifecycle migration.

- Exactly 20 single-send browser-observed samples per target class plus 50 unrelated-operation pairs; zero 57014, deadlock, timeout, automatic retry, duplicate, or unexpected browser error.
- Ten additional calibrated pairs submit from distinct actors within 100 ms and compare concurrent wall time with equivalent isolated sequential wall time; p95 concurrent/sequential must remain below `0.85`. Raw request, response, client timing, `server_time`, and `server_duration_ms` evidence is retained, but `server_time` is not misrepresented as a transaction-completion timestamp.
- Target RPC DB p95 under 500 ms and max under 2 s; HTTP/UI acknowledgement p95 under 2 s and max under 5 s; outer browser ceiling 7 s.
- Candidate p95 at least 50% faster than frozen same-scale v1; large-versus-small difference <=20% or 250 ms.
- Initial JS <=1,000 KB minified and <=300 KB gzip; cold shell <=450 KB; no jsPDF/XLSX in entry; first export <=2 s.
- Critical bootstrap waterfall depth <=3, payload <=750 KB and >=60% smaller than baseline; no full `app_state.data` read.
- 30 cold authenticated loads: candidate application safe-interactive p95 <=3.5 s and max <=5 s; common browser-observed visible-dashboard readiness is >=40% faster than the identically measured baseline. Login LCP p75 <=2.5 s, CLS <=0.1.
- Baseline and candidate evidence must use performance metric version 2. A browser initialization observer creates the identical visible-dashboard comparison mark in both builds; candidate `bp-safe-interactive` remains an independent absolute gate. Readiness, request cutoff, dependency depth, and response end use one browser clock; Playwright observation delay is diagnostic only. Expected request keys, critical resources, and responses are joined bidirectionally by hashed URL occurrence and fail closed in both modes on missing/duplicate/invalid/inverted timing, failed status, invalid transfer size, body-read failure, or required-JSON parse failure. API payload is decoded bytes with no `Content-Length` fallback, cold shell is browser-reported transferred bytes including navigation, and JavaScript decoded/gzip sizes remain separate. All budget failures are emitted in the same completed evidence result.
- Startup regressions must prove profile and organization requests begin before either settles; inactive/missing profile precedence over organization timeout/error/missing; active-profile fail-closed organization handling; reuse of the verified organization by normalized bootstrap; and zero persisted operational mutation dispatch before authoritative restore readiness followed by exactly one permitted dispatch afterward.

### Atomic critical-bootstrap gate

- Prove no-session performs no realtime subscription and no bootstrap RPC. Prove inactive/missing/revoked profile, inactive membership, no membership, ambiguous active organization, and cross-tenant access return no operational rows and remove the attempt channel.
- Prove the single App-module import overlaps the single realtime handshake; one Supabase client/channel/buffer/RPC is reused under StrictMode, restore retry, delayed import, delayed subscription, cancellation, logout, and account switch.
- Prove the bootstrap RPC never starts before the same attempt reaches `SUBSCRIBED`, returns exactly one supported contract version/actor/organization, performs no writes, reads no `app_state.data`, and leaves the compatibility row identity unchanged.
- Compare the RPC envelope and mapped `AppData` to the existing normalized builders on the frozen staging dataset, including inactive historical staff, null contacts, edited times, open pauses, recoverable hops, item/combo snapshots, archived catalog entries, variants, reusable stock, and empty/nonempty child collections.
- Reject missing/extra/malformed/duplicate/cross-tenant/oversized rows, dangling child relationships, partial collections, actor/organization mismatch, timeout, disconnect during RPC or catch-up, buffer overflow, and RPC failure. Executable row cases cover every returned collection and malformed text, enum, boolean, number, timestamp, array, nested record, nullability, and mapper-consumed compatibility value. No failed or ambiguous attempt is retried with the same run identity.
- Advance the legacy retry timer after each atomic failure and prove no second session/channel/RPC attempt occurs. Then use one explicit manual retry signal and prove exactly one reset and one fresh attempt, including StrictMode adoption. Default-off builds must retain the static App entry and its prior request waterfall.
- Hold account A's RPC or catch-up response, explicitly sign out/reset, complete account B's bootstrap, then release A. A must fail as superseded without changing B's organization cache, channel, snapshot, or reusable result.
- Cancel an unadopted preparation before realtime reports `SUBSCRIBED`; it must unsubscribe and reject immediately, perform no bootstrap RPC, and leave a later fresh attempt usable.
- After one successful atomic bootstrap, deliver a post-ready disconnect, dispose, remount, re-subscribe, prepare, and reload without a manual retry. The same cached failure must be returned through every path with no second session, channel, or RPC; one explicit manual reset may create exactly one fresh attempt.
- Dispose and immediately remount with the same callback identities while the old subscription has deferred hydration and readiness completions. Exercise hydration success and failure plus readiness success and failure. Neither old success nor old failure may notify the remount; a subsequent current-generation event must notify exactly once.
- Reject an otherwise well-shaped bootstrap response when either actor or profile `tabPermissions` contains a value outside the closed application `TabId` union. No mapper may silently coerce or retain an unknown permission.
- Mutate access-helper evidence independently for security-definer, definition hash, definition/body consistency, normalized body, owner, volatility, exact configuration, missing owner/authenticated grants, optional canonical PUBLIC access, unauthorized anonymous/service/custom grantees, wrong privileges, and grant options. Every unsafe mutation must fail closed, and rollback generation must restore and compare the complete captured ACL including PUBLIC and grant-option state.
- Fail the atomic RPC/mapping/catch-up path, then mount and remount the cached-data listener. Re-subscription must reuse the same failure without a second channel/RPC until one explicit manual reset.
- Hold account A's realtime row hydration, switch/reset to account B, attach B's listener, then release A. The superseded A pipeline must not warn B, move B to stale-cache, notify B, alter B's snapshot, or clear B's reusable result.
- Hold a realtime hydration under one mounted subscription, dispose it, and remount with the same callback functions before releasing the hydration failure. A unique subscription generation must prevent the old continuation from notifying the remount even when the channel generation is unchanged.
- Deliver compact events immediately before, during, and after the RPC; prove organization filtering, serialized order, duplicate suppression, exact-once catch-up, no stale resurrection, no write enablement before catch-up, and exactly one queued mutation dispatch afterward.
- Record browser-clock marks for session ready, realtime requested/ready, App-module completion, RPC requested/response, mapping, catch-up, and safe interaction. Require realtime requested before App-module ready. Across one fresh unique 30-load race, require safe p95 <=3,500 ms, max <=5,000 ms, LCP p75 <=2,500 ms, RPC p95 <=800 ms/max <=1,200 ms, catch-up-to-safe p95 <=100 ms/max <=200 ms, dependency depth <=2, and exactly one bootstrap RPC across the complete page lifetime with no critical direct profile/organization/history/report/audit/full-app-state reads.
- Keep the critical RPC decoded payload at or below 105% of the last valid candidate's 153,325-byte critical API result. Preserve the existing bundle, CLS, React commit, Inventory pagination, and deferred-history budgets. Inventory evidence must include finite nonnegative page bytes, per-load total bytes, and p95/max totals.
- On the production-sized staging catalog, prove that inventory-item and sale-variant `raw_data` contains only allow-listed fallbacks whose normalized column is null, never redundant snapshots or QA seed metadata, while legacy session/tab/combo/config fallback behavior remains intact. The complete decoded RPC response must remain at or below 160,992 bytes, and client mapping must reconstruct inventory/variant behavior from typed columns plus any permitted nullable fallback.
- No root commits attributable to the one-second clock after the runtime unit; active-panel commit p95 <16 ms and max <50 ms.
- Deferred Inventory history must return the frozen 1,506-row scale shape as exact-count URL pages `offset=0&limit=1000` and `offset=1000&limit=1000`, response bodies `1000 + 506`, contiguous `Content-Range` totals of 1,506, and only HTTP 200/206. Persist each sanitized page plus click-to-history-ready duration; require Inventory history p95 <=2 s and max <=5 s with no failed request or remote-error banner.
- Inventory network-complete and rendered-ready timing use 25 ms event polling rather than the default coarse assertion schedule; both values are retained so network delay is not confused with React render delay.
- Every candidate load proves successful dashboard-history traffic starts strictly after application safe-interactive and that the idle/user-intent Inventory chunk request also remains post-safe. Executable responsive tests cover initial desktop, initial mobile, breakpoint transitions, one-layout-only content/action parity, and listener cleanup.

Every case is passed, failed, blocked, or not run. Any required blocked/not-run case is NO-GO unless the approved spec explicitly narrows it with recorded risk acceptance.
